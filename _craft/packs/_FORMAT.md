# `_craft/packs/<pack-id>/` — the per-pack craft layer

Everything in `_craft/` that is *about a world* lives here. Everything that is about
**craft** stays shared: `CRAFT_SPINE.md`'s through-lines, `quiz-question.card.md`'s tests
and kill list, and the twelve fandom-neutral rules in `.claude/hooks/question-lint.py`
(`trait-name`, `hedge-option`, `displacement`, `intensifier`, `biography`, `gloss-clause`,
`so-much-as`, `appositive-verdict`, `filter-word`, `negation-list`, plus the structural and
shape checks). A rule about how a sentence works does not become a different rule because
the setting changed.

**Why this exists.** The vocabulary tiers and the `role-preemption` phrases used to be
module constants in `question-lint.py`, which was correct while there was one pack. With
two, a module-level word list stops being an incomplete answer and becomes a **wrong** one:
pointed at a Harry Potter bank it FAILs on `sith` in prose that contains none, waves
`horcrux` and `dementor` through unchecked, and fires `skinned-question` on every stem.

## Files

| File | Required | Read by |
|---|---|---|
| `vocabulary.md` | **yes** — its presence is what makes a directory a pack | `question-lint.py` (rules), `craft-gate.sh` (world-pressures), `--brief` (reviewer bundle) |
| `exemplars.md` | yes in practice | `craft-gate.sh` (injected as the target voice), `--selftest` (must lint clean), `--brief` |

## `vocabulary.md` format

Markdown with `##` sections. **Terms go inside fenced blocks; prose goes outside them.**

Markdown rather than JSON, for two reasons that are both load-bearing:

1. `craft-gate.sh` is POSIX `sh` with no guarantee of `jq`. `sed -n '/^## world-pressures/,/^## /p'` is trivial; parsing JSON in `sh` is not.
2. **The rulings have to travel with the words.** The most valuable content in the old
   constants was the commentary — why `sith` is DENY and not ALLOW, why `mandalorian` is
   not a costume swap-in, why `grogu` may appear in a result and never in a question. A
   format that cannot hold that readably loses it, and the next author "fixes" the list.

Terms inside fences are parsed by `question-lint.py`'s existing `_tier_terms()`:
whitespace-separated, `"quoted for multi-word"`. Case-insensitive everywhere.

| Section | Tier | Effect |
|---|---|---|
| `## aliases` | — | **One per line, unquoted.** Extra strings `craft-gate.sh` matches when sniffing which pack a prompt is about — the names a person would actually type. The pack id is always matched too. Unlike the tier sections these are NOT whitespace-separated terms: a whole line is one alias, so multi-word aliases work without quoting. |
| `## allow` | none | Ordinary vocabulary of this world — the register the card asks for. Fires **no** rule. Listed only so `skinned-question` has something to detect the *presence* of. |
| `## warn` | B, advisory | Legitimate but heavier. Cap of one per question; each should survive being deleted from the sentence. |
| `## deny` | **A, FAIL** | Trivia-only (a reader needs the source material to know what it means) or roster-collapsing. |
| `## register` | none | Words that carry the world without being proper nouns at all. Counts toward `skinned-question` like ALLOW does. |
| `## role-preemption` | **A, FAIL** | **Literal phrases, one per line.** Granting the taker a role, a side, a power or a possession that collapses the result space. |
| `## world-pressures` | — | Bulleted. The load-bearing facts of the setting that a diegetic dilemma is *generated by*. Injected verbatim by `craft-gate.sh`; read by the question-reviewer. Never parsed as terms. |

### `role-preemption` is phrases, never a regex

Every line is `re.escape`d before it becomes a pattern. A regex read from a data file can
crash the hook (which the "a crash must never block writing" contract forbids) or, worse,
silently match nothing and report clean. Need alternation? Write both lines.

## Rules for the vocabulary itself

Enforced by `question-lint.py --selftest`, which fails rather than warns on each:

- Every section present; `## deny` non-empty.
- **No term in two tiers.** A word in both ALLOW and DENY still FAILs `deny-noun` — the
  tiers are not checked in priority order, so a contradiction is silent by construction.
- No regex metacharacters in `## role-preemption`.
- Every routed pack (`src/lib/packs/*/`, except `_fixture`) has a directory here. A shipped
  bank with no vocabulary is an **under-linted** bank, which is worse than an unlinted one:
  it reports clean.
- **Cross-pack isolation:** no pack's DENY list may fire on another pack's ALLOW or
  REGISTER words. This is the `sith`-fails-on-a-Potter-bank regression, asserted directly.

## `exemplars.md`

**Each stem is ONE line.** The linter reads a prompt as the non-list line immediately above
its bullets, so a stem wrapped across two lines gets linted as its last fragment — and
reports clean on text nobody wrote.

Keep the per-unit commentary short. It is injected verbatim into every authoring turn and
the gate budget is real: with the spine and the card digest taking ~4.7 KB of 9000, a pack's
exemplars and world-pressures together have to fit in about 3.6 KB.

Five units, capped, per pack. The cap is the feature: five units get re-read every session,
a growing file becomes a style guide read once. A new unit that beats one is **swapped in
for the weakest, never appended.**

The exemplars outrank every prose rule in `_craft/`, including the card's own tests — if a
rule fires on an exemplar, **the rule is wrong and the unit is not.**

That authority is why they get audited hardest. An adversarial pass on the first
harry-potter set found four of five failed the substitution test *while their own
annotations asserted they passed* — a unit whose note claims a world-pressure the stem never
shows is the costumed defect with a certificate attached. The standing rule that came out of
it: **the mechanic must be visible in the stem, not in the annotation.** Do not accept an
exemplar on the strength of what its note says it does. `--selftest` enforces
this by linting each pack's exemplars under that pack's own vocabulary and requiring zero
Tier-A FAILs.

## One pack at a time

`craft-gate.sh` injects **one** pack's exemplars and world-pressures per turn, never two.
That is arithmetic before it is doctrine — the gate runs at ~8.3 KB against a hard 9000-byte
budget, and a second exemplar set is ~2.4 KB. It is also correct: you author one pack per
turn, and injecting the wrong voice is worse than injecting none. The gate prints which pack
it chose, so a wrong guess is visible and self-correcting. Selection order:

1. `$CRAFT_PACK`
2. the pack named in the prompt (id or alias, adopted only on a unique match)
3. `.claude/craft-pack`
4. the only pack installed
5. otherwise it does not guess — it warns and injects neither.
